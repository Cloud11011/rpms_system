## Workflow and concurrency definition

Documents: is_current=1 AND rpms_submitted_at IS NULL represents Pending Adviser Review, Needs Revision, or Ready for Formal RPMS Submission. Superseded or formally submitted versions are historical. Notifications: status=Sending or a currently held prism_notification_ID delivery mutex. Adviser-owned future Active deadlines cannot silently lose their audience/author authorization; cancel/reassign through Admin review before purge. Student stage/status/history alone are not blockers. No asynchronous document review/reassignment lease exists. Running DB mutations serialize on account rows; final snapshot guards already cover reports/notifications/uploads. Reassignment must additionally lock/revalidate the selected active Adviser before locking the Student. New deadlines must revalidate their active creator. Immediate email delivery must use the existing notification mutex too.

Common purge lock: prism_migrate (also migration lock), then active Admin authorization, target account, owned login, child rows and delivery mutexes. Existing independent writers may cause deadlock; retryable failure is safe and never reported deleted. READ COMMITTED and REPEATABLE READ remain supported. Every account has its own DB transaction; no hundred-account transaction. Account lifecycle changes use target row locks, and archive auditing becomes mandatory in-transaction.

## Purge and filesystem failure model

Student: lock/revalidate Admin and exact target; archive/hold/workflow/date/schema/ownership checks; discover all document versions, explicit exclusive reports/AI, recipient snapshots/notifications and attributable logs; validate exclusive safe physical paths/hashes and cross-account version edges; persist private immutable recovery manifest; quarantine files by rename on the same storage volume while account/child locks remain held; delete AI, documents, IERB, Student recipients, deadline memberships, exclusive reports, personal logs, tokens; detach institutional author links; delete profile/login; write minimal method-specific audit and durable job in the same transaction; commit; unlink quarantined files and only then mark completed/respond success.

Adviser: same eligibility/auth/schema gates; lock target then assignments; detach all Student assignments; detach institutional author and notification recipient relationships; cancel queued own delivery; preserve document/history/sender display text; delete tokens/profile/login; minimal audit/job; commit/finalize. Archive performs detachment and login deactivation transactionally with mandatory audit. Historical display text is never joined to a future same-named account.

Recovery: private random job directory under storage, immutable manifest bound to DB/server, account type/id and file hashes. Failure before commit restores quarantined files without overwriting any source. Uncertain commit leaves quarantine/journal for explicit Admin recovery: committed job means finalize; absent committed job plus existing exact target/references means restore. A journal or filesystem-finalization failure is reported as incomplete, with job id, never as purge success. Retry uses hashes and safe path checks, never unrelated filenames. Pending recovery blocks another purge of that same target until resolved. No unattended cleanup/cron. Corrupt/shared/symlink/outside files fail closed. Bounded per-account file discovery; operator review for excessively large accounts.

## Dates, Hold, Restore, override

DB NOW in Asia/Manila (+08:00) is authoritative. Manual eligibility archived_at+INTERVAL 7 DAY; six calendar months use DATE_ADD(archived_at, INTERVAL 6 MONTH) (month-end clamped by MariaDB). Warning interval is three days before that date, evaluated on Admin screens. Hold is structured, blocks every purge method, and removal is audited. Restore clears archive/hold/postponement, records restored_at, reactivates uniquely owned login according to role policy; credentials rotate to invalidate pre-archive sessions. Re-archive uses fresh DB NOW. Override is single account only, current Admin password + exact ID + mandatory reason + irreversible acknowledgement; bypasses only the grace date. Separate student/adviser_grace_period_override_purge audit, method grace_period_override.

## Implementation supplements after the read-only design

Final schema v9 contains 16 tables, 179 columns, 55 index components, 10 unchanged FK components and no triggers. The additive migration introduces 29 columns including the new job table, and 18 index components. Discovery checks cross-account version edges/shared files in sets, indexed by stored name, report filename and previous version. Student document/report ownership is capped at 2,000 file records; existing exclusive bytes at 256 MiB. Bulk selections cap at 10,000; HTTP chunks cap at 25 with a ten-second between-account budget. A single target's hashing/transaction can exceed that time.

Session tokens/previews expire after 15 minutes, refreshed during execution. Audit bulk markers close a lost COMMIT acknowledgement/session-checkpoint window; prior committed outcomes recover without repeating deletion. Incomplete batches are not evicted merely by creating another selection. At most twelve preview slots remain available; abandoned previews expire. A filter change during the asynchronous preview also invalidates the UI selection before any confirmation opens.

Late Student/document/exclusive-report audit writes lock the surviving Student before insertion, so they cannot recreate Student-owned data after purge. IERB edits and actual upload persistence also check pending recovery under their parent lock. Historical recycled emails/IDs are not treated as proof of someone else's unstructured audit ownership.

Recovery listing includes both disk journals and unfinished durable DB jobs. A missing journal is shown explicitly and cannot be finalized by inventing a file plan. Such a case needs operator backup/provenance review. Final implementation and exact validation totals are recorded in PRISM_RETENTION_PURGE_IMPLEMENTATION_REPORT.md.
