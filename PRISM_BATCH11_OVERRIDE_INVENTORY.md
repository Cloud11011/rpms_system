## Approved audit integration follow-up

The table above records the baseline inspected before edits. On 13 October 2026 the user approved the specific policy change: **"Approve atomic audit logging for existing overrides"**. `workflow.php::audit_override_atomic` uses the caller's transaction and existing audit columns, checks live ownership and propagates insertion errors for rollback. It neither commits nor starts an independent transaction.

Final mandatory paths: document review override, existing force submission, explicit IERB override, Admin progress changes through both IERB and Student edit routes, and existing reasoned deletion of a submitted document. For deletion the audit is inserted while ownership still exists, before DELETE, with version restoration in the same transaction; filesystem cleanup follows commit. Ordinary audits, stages, role scopes, reasons, recipients and account-retention services keep their existing contracts. `tests/batch11-atomic-audit.php` injects real INSERT failures across all six routes in the owned disposable database, compares every table and submitted file hashes, then verifies successful retries and rollback of an audit when a later DELETE fails. This approval grants no new override privilege or transition.
